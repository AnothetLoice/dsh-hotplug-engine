# ADR-0002 服务身份与契约版本化

- **状态**:已接受 | **日期**:2026-08-14
- **上位约束**:hotplug-engine-design.md §2-§5(服务契约)

## 背景
引擎对外暴露的身份(服务名/契约)一旦被消费方依赖,变更代价高;preview 期官方内核易变,需把"引擎契约"与"官方内核版本"解耦。

## 决策
1. ctx 服务名:`hotplugEngine`(`inject: ['hotplugEngine']` / `ctx.get('hotplugEngine')`)——与社区已用名 `pluginManager`(web-plugin-manager)不冲突;
2. 契约文档 `docs/01-contract.md` v1 为**唯一权威**;`src/contract/types.ts` 由其派生,不一致时以契约文档为准(先改文档再改代码);
3. **v1 内只增不改**:新增字段/方法必须向后兼容(旧消费方忽略新字段);破坏性变更 → 升 v2 + 新旧并行降级期;
4. 契约语义只随"官方机制事实变化"(经审计文档核对)而评估,不随官方版本号漂移。

## 备选
- 服务名复用 `pluginManager`:与社区插件冲突(同进程双实现),且语义不同(引擎≠管理器);
- 契约随官方 rc 版本走:消费方被官方版本抖动绑架,不可取。

## 后果
- 消费方(市场)只依赖稳定契约,不感知官方内核版本;
- 契约变更成本前置到"升 v2"流程,倒逼首版契约设计完整。
